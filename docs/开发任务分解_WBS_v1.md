# 开发任务分解（WBS）v1.0

> 本文档是 [游戏设计文档 GDD](游戏设计文档_GDD_v1.md) 的配套执行文档，面向**AI 编码助手和开发者本人**。
> GDD 回答"做什么、为什么"；本文档回答"怎么做、做到什么程度算完成、谁来做"。
> 数值以 [塔防数值表](塔防数值表_v1.md) 为准；历史依据见 [武器投入时间表](俄乌战争塔防_武器投入时间表.md)。

## 0. 使用说明（AI 必读）

### 0.1 人工参与程度标记

| 标记 | 含义 | AI 的做法 |
|---|---|---|
| 🟢 **AI 主导** | AI 可以独立完成，人只需抽查结果 | 直接实现，跑通测试后提交 |
| 🟡 **AI + 人工审核** | AI 完成主体，**必须由人审核或做关键决定**后才算完成 | 实现后列出需要人确认的点，等待确认 |
| 🔴 **人工主导** | 依赖审美、手感、判断、真实账号或法律责任，**需要大量人工参与** | AI 只做准备工作（草稿、选项、工具、清单），不替人做最终决定 |

### 0.2 任务格式

每个任务都有以下字段：

- **ID**：`WSxx-nnn`（xx = 工作块编号，nnn = 序号）
- **阶段**：M0–M6（见 GDD 第 18.2 节）
- **依赖**：必须先完成的任务 ID
- **输出**：具体的文件或产物路径
- **验收**：可以检查的完成标准
- **人工**：🟢 / 🟡 / 🔴

### 0.3 全局约束（所有任务都必须遵守）

1. **引擎与语言**：Godot 4（.NET 版）+ C#。只使用 **Godot 4 的 API**，不要使用 Godot 3 的写法（例如不要用 `KinematicBody2D`、`yield`、`export var`）。.NET 版本以 Godot 当前稳定版的要求为准。
2. **模拟层独立**：`sim/` 目录下的代码**禁止引用任何 Godot 命名空间**，必须能用 `dotnet test` 在命令行独立运行。
3. **确定性**：模拟层只使用项目自带的随机数生成器（`SimRandom`，以种子初始化），禁止使用 `System.Random`、`DateTime.Now`、`Guid.NewGuid()`、多线程中的非确定性顺序、`Dictionary` 的遍历顺序作为逻辑依据。
4. **数据驱动**：单位、武器、敌人、关卡、波次的参数一律放在 `data/` 的 JSON 中，代码里不写死数值。
5. **测试**：`sim/` 中的每条规则都要有单元测试；修改后必须让 `dotnet test` 全部通过。
6. **命名**：代码标识符用英文；注释和文档用中文；数据中的显示文本通过本地化键引用（见 WS07）。
7. **文档同步**：实现若与 GDD 或数值表不一致，**先停下来说明差异**，由人决定改代码还是改文档。
8. **提交**：一个任务一个提交，提交信息格式 `[WSxx-nnn] 简短说明`。
9. **敏感内容**：遵守 GDD 第 17 章（玩法目标是保护；人物、部队、设施虚构；数值抽象；电子战只描述效果）。

### 0.4 AI 执行任务的标准流程

```
1. 读取任务条目 + 引用的 GDD 章节 + 相关数值表
2. 检查依赖任务是否完成
3. 如果有不明确之处：列出问题，等待回答（不要自行假设重大设计）
4. 实现 → 编写 / 更新测试 → 运行 dotnet test（或 Godot 无头运行）
5. 按"验收"逐条自查
6. 🟡 / 🔴 任务：输出"需要人工确认的事项"清单
7. 提交
```

## WS01 模拟核心

**目标**：实现一夜空袭的全部规则，可以脱离引擎、无画面、确定性地运行。
**参考**：GDD 第 6、7、8 章；数值表全部。

### 01.A 基础规格

| 项目 | 规格 |
|---|---|
| 时间单位 | 模拟内部使用**真实世界秒**（world seconds）。默认播放速度：1 现实秒 = 60 世界秒（即"1 游戏秒 ≈ 真实 1 分钟"）。数值表中的"游戏秒"× 60 = 世界秒 |
| 步长 | 固定 1 世界秒一步（`Tick`）。快速目标（导弹、拦截弹）不做逐帧碰撞，而是**解析计算拦截时间点**，到点后掷骰判定 |
| 坐标 | 二维平面，单位米，x 向东、y 向北；高度单独存储（米，相对地面） |
| 地图尺寸 | 最大 400 × 400 km（A 线远程系统）；B 线通常 20–60 km |
| 随机数 | `SimRandom`：PCG32 或 xoshiro256**，种子来自关卡 + 夜晚序号；每个子系统使用独立的派生流，避免改动一处影响全局 |
| 浮点 | 使用 `double`；避免平台相关的数学函数差异影响逻辑判断（回放只保证同平台一致） |
| 实体存储 | 按类型分组的数组（结构体数组或类列表均可），用整数 ID 引用；**不要**使用面向对象的深继承 |

### 01.B 每一步的系统执行顺序（固定，写进 `SimWorld.Step()`）

```
1  WaveSpawnSystem        按波次脚本生成敌方目标
2  EnemyMovementSystem    敌方按航线移动（航点、高度剖面、绕行）
3  SensorSystem           各传感器生成原始探测（距离、高度、地形遮挡、天气）
4  TrackFusionSystem      合并探测 → 航迹（模糊 / 大致 / 精确），诱饵甄别
5  ElectronicWarfareSystem 计算电子战覆盖，修改敌方精度、链路状态
6  EmissionSystem         按辐射策略和触发规则决定雷达开关
7  EngagementSystem       按交战规则选目标、分配弹药、发射
8  InterceptorSystem      拦截弹飞行；到达拦截点时判定命中（拦截概率 × 修正）
9  ExternalSupportSystem  战斗机、国家级电子战等
10 ImpactSystem           命中地面：伤害、溅射、碎片、电网连锁
11 ExposureSystem         更新暴露度
12 EnemyIntelSystem       敌方 AI 更新已知目标清单（试探结果、暴露度）
13 ScoringSystem          交换比、损失、信任度变化
14 EventLog               输出本步事件
```

### 01.C 与外部的接口

| 接口 | 方向 | 内容 |
|---|---|---|
| `SimWorld.Create(LevelData, SimConfig, seed)` | 入 | 创建一夜战斗 |
| `SimWorld.Enqueue(ICommand)` | 入 | 玩家指令（带生效时刻）：部署、改规则、指挥点操作、呼叫支援、回答二选一 |
| `SimWorld.Step()` | — | 推进一步 |
| `SimWorld.Snapshot` | 出 | 只读状态快照，供渲染和界面读取 |
| `SimWorld.DrainEvents()` | 出 | 事件流：发射、拦截、命中、预警、反辐射来袭、二选一请求、单位被毁…… |
| `NightResult` | 出 | 一夜结束后的结算：损失、弹药消耗、暴露度、交换比、跨关数据 |

**回放 = 种子 + 指令列表**。相同输入必须得到逐步一致的快照（WS01-020 测试保证）。

## WS02 关卡与地图

**目标**：为每一关提供地形、城市、保护目标、电网、来袭方向、波次和部署位置。
**参考**：GDD 第 12 章（关卡卡片）、第 11 章（时间结构）。

### 02.A 关卡数据格式（`data/levels/<level_id>/`）

| 文件 | 内容 |
|---|---|
| `level.json` | 元数据：编号、名称（本地化键）、主角、日期范围、时间结构类型（A–E）、战斗机模式、胜负条件、可用单位与数量、配额、城市资源速率、指挥点 |
| `map/heightmap.png` | 16 位灰度高程图 + 比例（米 / 像素） |
| `map/layers.json` | 矢量图层：河流、道路、桥梁、城区多边形、森林、边境线、禁止交战区 |
| `map/structures.json` | 保护目标：类型、位置、权重、HP、所属电网节点 |
| `map/grid.json` | 电网拓扑：节点、连线 |
| `map/deploy.json` | 可部署区域、备用阵地、不可部署区（水面、城区中心等） |
| `waves.json` | 每夜的波次：时间、来源方向、敌人类型与数量、航线模板、AI 行为标签 |
| `intel.json` | 每夜简报情报（可能包含不准确信息） |
| `events.json` | 剧情事件（例如 Oreshnik）与触发条件 |

## WS03 美术与特效

**目标**：写实 2.5D 的实景层与指挥层（GDD 第 16.1–16.2 节）。
**整体人工程度**：🔴。AI 能显著加速生产，但**风格决定、外形准确性、最终品质**需要人把关。

### 03.A 规格（WS03-002 确定后写入本节）

| 项目 | 内容 |
