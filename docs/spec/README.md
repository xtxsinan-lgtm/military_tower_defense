# 系统规格（docs/spec/）

> 本目录是 **GDD → 代码** 之间的一层：把 GDD、数值表描述的规则写成"照着就能实现"的规格。
> 优先级：设计意图以 GDD 为准，数值以数值表 / `data/` 为准，**实现细节以本目录为准**。
> 规格与 GDD / 数值表冲突时，不得自行裁决，写进该文件的"待决问题"，由人决定。

## 每个规格文件的固定结构

```markdown
# <编号> <标题>

## 0. 范围与依据
- 覆盖哪些系统；引用的 GDD 章节、数值表段落、data 文件与字段
- 依赖哪些其他规格（只依赖编号更小的文件，00_core 例外）

## 1. 数据输入
- 用到的 JSON 字段（文件 → 字段 → 单位 → 加载后换算成什么）

## 2. 状态
- 每个实体 / 组件的字段：名称、C# 类型、单位、初值、谁写谁读
- 用表格写，字段名就是最终代码里的名字（英文）

## 3. 每步算法
- 在 SimWorld.Step() 中的位置（WBS 01.B 序号）
- 伪代码（确定性：遍历按 ID 升序；随机数写明用哪个子流）
- 所有公式写成可直接实现的形式，带单位

## 4. 事件与命令
- 本系统产生的事件（名称、字段）；响应的命令（名称、字段、生效时刻）

## 5. 边界情况
- 逐条列出（例如：目标在拦截弹飞行途中被别人击落、弹药为 0、单位在撤收中被命令开火……）以及处理方式

## 6. 不变量
- 任何时刻都必须成立的条件（可写成断言）

## 7. 测试用例
- 编号 T-<文件号>-<序号>；每条写：手写的小型输入数据（不依赖正式数值）、操作、精确的预期输出（数字）
- 每条规则至少一条；概率类规则用固定种子 + 期望序列，或用"强制骰值"的测试钩子

## 8. 待决问题
- 规格作者无法从 GDD / 数值表推出、需要人决定的点；每条给出建议默认值
```

## 写作规则

1. **不发明重大设计**：GDD / 数值表没说的玩法规则，写进"待决问题"并给建议默认值；纯实现细节（数据结构、函数拆分）可以自行决定。
2. **数值一律引用数据字段**，不在规格里写死正式数值；测试用例用手写的小数字。
3. **确定性**：遵守 AGENTS.md 第 3 节第 3 条；每个用到随机数的地方写明子流名（见 00_core 的子流表）。
4. **术语**：中文写说明，标识符用英文；同一个概念全目录只用一个名字（以 00_core 的术语表为准）。
5. **敏感内容**：遵守 GDD 第 17 章。
