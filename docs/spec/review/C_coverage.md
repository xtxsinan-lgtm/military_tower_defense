### 3.3 确定性优化建议（都保持"同输入 → 同输出"）

**A. 与朴素算法逐位等价的优化**（T1，直接写进规格并加等价性测试）

1. **公共空间索引 `ThreatGrid`**（00 登记，系统 2 之后每步重建）：均匀网格（格长取 `max(5 km, 地图边长 / 64)`），每格存目标 ID 升序列表；圆形查询返回的 ID **按升序归并**，规格写明"结果集合与顺序必须等于全表扫描后过滤"。02 的 `RangeDetect` / `FireControlDetect` / `WarnTrack`、03 的候选粗筛、04 的 `ProbeCheck` 共用。
2. **交战排序下界懒求值**：对每个合格候选先算下界 `lb = max(0, (d3D − rFloor) / (vi + vtMax))`（`d3D` 当前三维距离，`vtMax` 见 C-T1-03），按 `(Key1, lb, track.Id)` 进入优先队列；依次弹出、对其精确 `SolveFor` 得 `Key2` 放入第二个有序集合；当第二个集合的最小 `(Key1, Key2, Id)` 不大于队首的 `(Key1, lb, Id)` 时，它就是精确排序中的下一个。PostCheck 失败则继续。结果与"全部求解后排序"逐位相同。
3. **`Solve` 采样起点**：`k0 = max(1, floor(d3D / (vi + vtMax)))`，从 `k0` 开始逐秒采样（`k < k0` 时 `Reach` 必为假；`Arrived` 单调，跳过不改变返回值）。二分区间与朴素算法相同，结果逐位相同。
4. **`Assigned` / `ArmAssigned` 增量计数**：`EnemyIntelState` 内维护 `UnitId → 存活目标数`、`Pos → 存活目标数`（只查找不遍历，01 生成与 00 删除时更新）。
5. **A\* 缓存**：键 `(ti, A50Active, s, g, AvoidanceSiteKey 版本号)`；不参与哈希、可随时清空；与 01 §3.3.4 的缓存规则同一表述。
6. **融合分组**：`Detection` 存为结构体列表；按 `ThreatId` 计数排序（ID 稠密，用"ID − 最小 ID"做下标），误报键另排；组内顺序 = 原产生顺序。

**B. 会改变结果、需要人确认数值的优化**（T2）

1. **二分次数 48 → 32**：1 秒区间二分 32 次分辨率 2.3e-10 s（以 1 km/s 计 0.2 µm），48 次已低于 `double` 在 t ≈ 100 s 处的精度（ulp ≈ 1.4e-14 s），后 10 余次基本是空转。改为 32 次后 T-03 的预期值变化在 1e-9 容差内，但逐位断言（`==`）须重算（C-T2-10）。
2. **分段解析解**：01 已提供 `Legs()`；线性段（高度匀速变化）的"最早可达时刻"是二次方程的最小正根，可直接求出；抛物线段仍用二分。这会消除"可达窗口落在两个采样点之间被漏掉"的已知近似（03 §3.1 末、B-T2-65），属于规则变化，建议 M3 性能任务时再定。
3. **传感器可见性**：见 C-T2-01（地平线表本身就是 B 类：它是新定义，不是等价加速）。

### 5.2 规格之间的口径

- 00 / 01 / 02 / 03 / 04 / 05 / 06 对"游戏秒 × 60 = 世界秒"的使用**一致**，没有发现某处按游戏秒直接参与每步运算的错误；所有带 `GameSec` 的字段都在加载层换算。
- 唯一的系统性问题不在换算，而在**现实时间**：GDD 把"慢放 0.5×"写成相对 60 倍速的倍率，换算后仍是 30 倍速，空袭中"慢放 + 二选一"失去意义（C-T3-01）。
- 次要：01 把数据速度当水平速度（B-T2-23 已批准），使大落角弹道目标的末段三维速度远超数值表；在 H-11 的推演中，这让 PAC‑3 只有一次射击机会（C-T2-09）。

- 建议：01 §3.2.9 增加 `ThreatKinematics.MaxSpeed3DMps(th) = Math.Max(th.SpeedMps, th.TerminalSpeedMps) × Math.Sqrt(1 + slope²)`，`slope` = `Linear`：`(A0 − AEnd) / (L − sD)`（`L == sD` 时 0）；`Parabolic`：`2 × A0 / L`；`Arrived` / `Holding` 返回 0。03 粗筛改为 `dNow <= R + MaxSpeed3DMps(t) * TMax + Eps`。
